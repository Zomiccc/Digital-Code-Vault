# Signing Schemes — Internal Reference

There are **two independent HMAC-SHA256 (hex)** schemes in this system.
They use different keys and sign over different inputs. Do not conflate them.

---

## Scheme A — Outbound Request Signing (Connector → Platform)

Used when the connector calls `POST /api/v1/webhooks/endpoints` (or `GET`/`DELETE`)
to register, list, or delete a webhook endpoint.

### Headers sent

| Header         | Value                                                  |
|----------------|--------------------------------------------------------|
| `X-Api-Key`    | The merchant's full API key string (e.g. `pk_xxx.yyy`) |
| `X-Timestamp`  | Current epoch milliseconds (string)                    |
| `X-Signature`  | HMAC-SHA256 hex digest (see below)                     |

### Canonical string

```
METHOD\nPATH\nBODY\nTIMESTAMP
```

- **METHOD** — uppercase HTTP method (e.g. `POST`)
- **PATH** — the request path as the server sees it in `req.originalUrl`,
  which includes the `/api/v1` global prefix (e.g. `/api/v1/webhooks/endpoints`)
- **BODY** — `req.rawBody?.toString() ?? ''`. The server enables Nest's `rawBody: true`
  option, so this is the **exact raw JSON body bytes** transmitted with the request
  (empty string `''` for GET/DELETE requests with no body). Connectors MUST sign over
  the exact byte-for-byte string sent as the request body — do not re-serialize a
  parsed object, since key ordering/whitespace differences will break verification.
- **TIMESTAMP** — same epoch-millisecond string sent in `X-Timestamp`

### HMAC key

The **full API key string** itself (e.g. `pk_xxx.yyy`).

> **Important:** There is no separate "API secret" in this backend.
> `ApiKeyGuard` (line 78) passes `secret: apiKey` to `verifyHmacSignature`.
> The API key serves dual purpose: identification (via argon2 hash lookup)
> and HMAC signing key.

### Timestamp window

Must be within `HMAC_TIMESTAMP_WINDOW_MS` (default 300000 ms / 5 min) of server time.

### Source references

- `apps/api/src/auth/guards/api-key.guard.ts:74-84` — extracts method, path, body, calls verifyHmacSignature
- `apps/api/src/auth/auth.service.ts:472-484` — builds canonical string, computes HMAC
- `apps/api/src/encryption/encryption.service.ts:85-87` — hmacSha256 implementation

## Scheme B — Inbound Delivery Verification (Platform → Connector)

Used when the platform delivers a webhook event to a registered endpoint URL.
The connector must verify the signature on receipt.

### Headers sent by platform

| Header               | Value                                                    |
|----------------------|----------------------------------------------------------|
| `X-Webhook-Signature`| HMAC-SHA256 hex digest (see below)                       |
| `X-Webhook-Event`    | The event name (e.g. `order.fulfilled`)                  |
| `Content-Type`       | `application/json`                                       |

### Signed input

The **exact raw JSON body** (the complete HTTP request body string).

```
signature = HMAC_SHA256(endpointSecret, rawBody)  // hex
```

- **rawBody** — `JSON.stringify({ event, ...data, timestamp })` as sent by the server
- No canonical string, no METHOD/PATH/TIMESTAMP — just the raw body bytes.

### HMAC key

The **endpoint `secret`** returned in the registration response body:
`{ id, url, status, secret }` (see `webhook.service.ts:248-253`).

This is a 32-byte random hex token generated by `encryptionService.generateToken(32)`.

### Source references

- `apps/api/src/webhooks/webhook.service.ts:118-151` — deliverWebhook: builds body, computes signature, sends POST
- `apps/api/src/webhooks/webhook.service.ts:233` — secret generation at registration

## Summary table

| Aspect              | Scheme A (outbound)                    | Scheme B (inbound)                      |
|---------------------|----------------------------------------|-----------------------------------------|
| Direction           | Connector → Platform                   | Platform → Connector                    |
| HMAC key            | Full API key (`pk_xxx.yyy`)            | Endpoint `secret` from registration     |
| Signed input        | `METHOD\nPATH\nBODY\nTIMESTAMP`         | Raw JSON body string                    |
| Header carrying sig | `X-Signature`                          | `X-Webhook-Signature`                   |
| Digest format       | hex                                    | hex                                     |
